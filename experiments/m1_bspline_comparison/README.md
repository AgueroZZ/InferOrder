# Single-ordering recovery from a shared PCA initialization

This replicated experiment compares MPCurve, Hastie–Stuetzle principal curves,
classical GPLVM, and Bayesian GPLVM on random cubic B-spline trajectories.
The question is how well each fitted method recovers sample order from the same
one-dimensional PCA initialization. The workflowr report is
`analysis/simulation_m1_comparison.Rmd`; numerical summaries and PNG/PDF figures
are generated by `summarize.R`.

## Results

| Method | Low-noise median absolute Spearman | High-noise median absolute Spearman |
| --- | ---: | ---: |
| Initial PCA | 0.620 | 0.552 |
| MPCurve | 0.612 | 0.550 |
| Principal curve | 0.526 | 0.495 |
| GPLVM | 0.632 | 0.566 |
| Bayesian GPLVM | 0.615 | 0.554 |

Paired mean comparator-minus-MPCurve differences range from -0.014 to +0.010,
each smaller in magnitude than its Monte Carlo SE. This design does not establish
a consistent advantage for a comparator, and does not establish equivalence.
Principal curves exceed 0.95 recovery in three low-noise replicates, but also
lose more than 0.05 relative to PCA in 12/30 low-noise replicates, as often as they
gain more than 0.05. All 240 fits have finite endpoints. MPCurve and GPLVM converge
in 60/60 fits, principal curves in 42/60 (18 iteration caps), and Bayesian GPLVM in
59/60 (one line-search error). R fits emit no warnings; GPy dependency deprecation
warnings are retained in the JSON artifacts.

## Fixed design

There are 30 independent curve realizations, each with 200 samples and 12
features. Within a replicate, sample positions are independent Uniform(0,1).
Each feature has eight cubic B-spline coefficients drawn independently from
N(0,1), with boundary knots 0 and 1 and interior knots 0.2, 0.4, 0.6, 0.8.
Features share one sample position; no feature is constrained to be monotone.
Each trajectory is centered on a 2,001-point uniform grid, and a common scale
sets the average squared centered value across grid positions and features to
one. Thus features retain relative amplitude differences.

Independent Gaussian errors have SD 0.25 (low noise) or 1 (high noise), giving
average variance SNR 16 or 1 under that dense-grid definition. Each replicate
uses the same curves, sample positions and standard-normal errors at both noise
levels. Replicates are independent; the two noise conditions are paired.
All four methods receive the same column-centered sample-by-feature matrix;
features are not standardized by observed variance. The shared PC1 is computed
once per dataset, then centered and scaled to population variance one. Truth is
used only to generate observations and evaluate the resulting sample order.
Settings were fixed before the first timing run and were not selected by recovery.

## Implementations and stopping

- MPCurver 0.3.4, frozen release commit
  `15f2b0bbe5dfa61cd46da5160b2bc251e75a0475`, as in the preceding pilot.
  Single-ordering CAVI, K=50, RW2, quantile-bin PCA initialization, initial
  smoothness precision 1, learned per-feature noise and precision, adaptive
  position weights. The pilot's `.cavi_build_from_ordering` entry point uses
  relative ELBO tolerance 1e-6 and at most 2,000 sweeps. The saved zero-sweep
  initialization has 50 ordered bins, so it introduces ties within PCA ranks.
- R princurve 2.1.6. The initial geometric curve is the PC1 line, with its
  points ordered along PC1 before projection. Default smoothing splines have
  df=5 and endpoint stretch=2. As in the tighter pilot control, projection
  distance tolerance is 1e-6 and the cap is 1,000 iterations. Actual initial
  projection ranks are checked against PC1. The smoother df is fixed rather
  than selected using truth.
- GPy 1.13.2 GPLVM, latent dimension one, native RBF plus bias covariance.
- GPy 1.13.2 BayesianGPLVM, latent dimension one, native RBF covariance and
  50 inducing points. Latent posterior means receive the shared PC1 directly;
  native random latent variances and inducing-point selection use the recorded
  replicate-specific seed, shared between noise conditions. Ordering is evaluated
  using latent posterior means.

Both GP methods receive explicit coordinates, bypassing GPy's internally
standardized PCA. Both optimize kernel parameters, noise, and latent variables
with L-BFGS-B, gtol=1e-5 and bfgs_factor=1e7. There are up to three blocks of
2,000 evaluations each; only evaluation-limit terminations trigger continuation.
Methods use their own stopping criteria. Convergence flags describe those rules,
not attainment of a global optimum. All finite endpoints, including budget-limited
ones, contribute to plots and summaries; no endpoint is selected using truth.
Timing includes initialization and runs with one BLAS thread per fit; GP workers
run concurrently, so timing is descriptive and not a dedicated speed benchmark.

## Metrics and saved artifacts

The primary metric is absolute Spearman correlation between true t and inferred
position, allowing a global reversal. Ties use average ranks. Absolute Kendall
correlation is a secondary check. PCA appears as a baseline; gain is final minus
initial absolute Spearman. Paired differences are comparator minus MPCurve on
identical data. Monte Carlo standard errors use the SD of those 30 differences
divided by sqrt(30). They describe simulation sampling error within each condition.
No multiplicity-adjusted superiority claim is made.

`inputs/` contains generating coefficients, curves, noise, truths and explicit
PCA coordinates. `results/` contains full R fits and GP initial/final parameters,
coordinates, statuses and warnings. `manifest.csv` records seeds and input hashes.
`metrics.csv`, `summary.csv`, `paired_summary.csv`, and `positions.csv` preserve
numeric results. `verification.txt` records current checks. `source/` retains the
MPCurver source archive used to install the frozen fitting library.

## Reproduction

From the InferOrder root, reuse the pilot's frozen R library and Python environment:

```bash
bash experiments/estimate_intrinsic_m_smooth_v032/run_r.sh experiments/m1_bspline_comparison/prepare.R
bash experiments/estimate_intrinsic_m_smooth_v032/run_r.sh experiments/m1_bspline_comparison/run_r_methods.R
experiments/estimate_intrinsic_m_smooth_v032/exploratory_m5_ordering_b/external_methods/.venv/bin/python experiments/m1_bspline_comparison/run_gpy.py --workers 3
bash experiments/estimate_intrinsic_m_smooth_v032/run_r.sh experiments/m1_bspline_comparison/summarize.R
bash experiments/estimate_intrinsic_m_smooth_v032/run_r.sh experiments/m1_bspline_comparison/verify_generator.R
bash experiments/estimate_intrinsic_m_smooth_v032/run_r.sh experiments/m1_bspline_comparison/build_site.R
python3 scripts/check_current_site.py
```

`python_requirements.txt` and `python_freeze.txt` record Python dependencies;
`R_session.txt` records R dependencies. If rebuilding the environment, install the
saved source archive and princurve 2.1.6 into the library locations specified in
`common.R`, and create the Python environment at the path above using the pinned
requirements. Existing fit files are resumable checkpoints; to change design or
settings use a new experiment directory, rather than reusing these endpoints.
